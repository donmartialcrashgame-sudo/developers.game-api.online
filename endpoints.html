1. Endpoint overview

The production API host is api.game-api.online. REST requests use HTTPS. Realtime events use the WebSocket endpoint below.

HTTPS
https://api.game-api.online
Primary production API host.
WSS
wss://api.game-api.online/realtime
Production realtime WebSocket endpoint for live game events.

3. Crash Game endpoint

The Crash Game rounds endpoint returns recent round records. The server controls the live round lifecycle; clients consume the published state.

Request

POST https://api.game-api.online/api/v1/crash/rounds
Authorization: Bearer YOUR_GAME_API_KEY
Content-Type: application/json

{
  "limit": 20
}

Response shape

{
  "success": true,
  "game": "crash",
  "data": [
    {
      "id": "round-id",
      "round_number": 125,
      "status": "crash",
      "multiplier": "3.47",
      "started_at": "2026-09-24T08:00:00.000Z",
      "crashed_at": "2026-09-24T08:00:07.000Z"
    }
  ],
  "count": 1,
  "plan": "free"
}
Read-only game flow: the live server owns the Crash Game lifecycle. A client connects and receives published state; it does not start or manually crash a round.

4. WebSocket realtime endpoint

Use the production WebSocket URL to receive live Crash Game events without repeatedly polling the REST endpoint.

WSS
wss://api.game-api.online/realtime
Secure WebSocket connection for realtime Game API events.

Connection flow

  1. Open wss://api.game-api.online/realtime.
  2. The server sends a connected message.
  3. The Crash Game stream is available as crash_rounds.
  4. If your integration requires API-key authentication, send an auth message with your API key.
  5. Read crash_status updates as the server moves through betting, running and crash states.

Browser example

const socket = new WebSocket("wss://api.game-api.online/realtime");

socket.onopen = () => {
  socket.send(JSON.stringify({
    type: "auth",
    apiKey: "YOUR_GAME_API_KEY"
  }));
};

socket.onmessage = (event) => {
  const message = JSON.parse(event.data);
  console.log("Game API:", message);
};

Typical live message

{
  "type": "crash_status",
  "status": "running",
  "round_number": 125,
  "multiplier": "3.47",
  "started_at": "2026-09-24T08:00:00.000Z"
}

5. Authentication

Game API uses API keys for protected game endpoints. Keep production secrets on a trusted backend and never expose a secret key in public client-side source code.

API key header

Authorization: Bearer YOUR_GAME_API_KEY

Use the API key issued for your Game API account when calling protected game endpoints.

WebSocket authentication

{ "type": "auth", "apiKey": "YOUR_GAME_API_KEY" }

Authenticate a WebSocket connection after it opens when authentication is required by the environment.

Security: do not place production API secrets inside frontend JavaScript, public GitHub repositories, screenshots or mobile-app bundles where they can be extracted.

6. Integration examples

JavaScript REST request

const response = await fetch(
  "https://api.game-api.online/api/v1/crash/rounds",
  {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "Authorization": "Bearer YOUR_GAME_API_KEY"
    },
    body: JSON.stringify({ limit: 20 })
  }
);

const result = await response.json();
console.log(result);

cURL

curl -X POST   "https://api.game-api.online/api/v1/crash/rounds"   -H "Authorization: Bearer YOUR_GAME_API_KEY"   -H "Content-Type: application/json"   -d '{"limit":20}'

7. Errors and troubleshooting

SituationWhat to check
Invalid API keyConfirm the key is active, has not been revoked or expired, and is being sent in the expected authentication field.
401 / unauthorizedCheck the Authorization header and make sure the token belongs to the intended Game API account.
WebSocket auth_errorCheck the API key and send the auth message only after the WebSocket connection opens.
Empty round dataCheck the selected game, account plan and whether round records are currently available.
CORS in a browserFor production secret keys, use a backend proxy rather than exposing credentials directly to the browser.
